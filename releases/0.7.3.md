# Usage Monitor 0.7.3 Win11 Bar 可见性修复预览（2026-10-13）

用户在 Win11 上反馈：v0.7.2 切到 Bar 后无显示，切回浮窗正常。提供的日志显示子窗口 visible=true、48 像素高且位于任务栏内；此前仅核对挂载关系不足以证明内容真正可见。当前诊断指向子窗口/合成层遮挡，尚无 Win11 渲染抓取可最终确认。

## 修复

- Win11 Bar 改为任务栏内部的独立合成窗口，在通知区左侧显示；初始化分层窗口的不透明度，避开 Explorer 子窗口裁剪/合成遮挡路径。正常显示位置仍在任务栏范围内。
- Win10 保留子窗口嵌入。Win11 新窗口不依附 Explorer 的父/所有者关系，随测得的任务栏隐藏/屏外/全屏状态隐藏恢复。
- AppBar 不再受浮窗最小尺寸限制。补充 build、父窗口、DPI、可见状态、回退原因和 Neon 绘制诊断日志。

## Win11 复测

1. 托盘右键 → 软件更新 → 检查更新 → 安装更新并重启（需开启接收预览版）；或退出旧版后安装本目录安装包。便携 EXE 先复制到本机固定目录。
2. 选择「嵌入任务栏 (AppBar)」，检查条是否出现在任务栏内、通知区左侧；分别尝试只显示 Codex 和同时显示多项服务，再切换两主题。
3. 检查浮窗/Bar 来回切换、时钟与图标点击、自动隐藏及恢复、全屏退出、缩放和 Explorer 重启。图标过多仍可能重叠，本版不预留图标空间。
4. 若仍无显示，反馈新日志的 `[appbar]`、`[paint_appbar]` 行与 Win11 build。日志位于 `%LOCALAPPDATA%\UsageMonitor\_runtime_logs\usage-monitor.log`；status=2 表示已走新合成路径，3/4 表示主动隐藏，5–7 表示失败回退。
